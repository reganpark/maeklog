# Maeklog 소스 설치 가이드

[English](setup.md) · [한국어](setup.ko.md)

[← 소개로 돌아가기](../README.md)

Maeklog 소스는 [reganpark/maeklog](https://github.com/reganpark/maeklog)에서 제공하며, [Herdr Marketplace](https://herdr.dev/plugins/)의 자동 검색 대상에도 포함되어 있습니다. Marketplace 색인은 30분마다 갱신됩니다. 이 가이드는 로컬에 받은 소스로 직접 설치하는 방법을 설명합니다. 설치하려면 아래의 훅 신뢰 승인과 통합 Codex 클라이언트도 필요합니다.

**Maeklog 빌드·연결 → 네 훅 등록·신뢰 → 준비 상태 확인 → 통합 Codex 빌드 → 새 대화 확인** 순서로 진행합니다. 클라이언트 패치는 패널에 필요한 탭 식별 정보와 공개 진행 정보를 제공합니다.

## 시작하기 전에

| 준비물 | 세부 사항 |
| --- | --- |
| 운영체제 | 실제 실행 검증 범위는 Linux x86_64입니다. macOS는 실험적 지원 대상이며, 실제 하드웨어에서는 아직 검증하지 않았습니다. |
| Herdr | 0.8.2 이상. 셸 명령은 Herdr 안의 일반 셸에서 실행합니다. |
| Codex | 로그인한 공식 CLI와 활성화된 hooks 기능이 필요합니다. 현재 통합 패치의 대상 버전은 0.162.1입니다. |
| 빌드 도구 | Python 3.11 이상, Git, GitHub CLI(`gh`), Rust/rustup, `just`, `cargo-nextest`, Node.js/npm, Bazel 9.2.0 또는 Bazelisk가 필요합니다. `bazel` 명령이 PATH에서 실행되어야 합니다. Maeklog는 Rust 1.97.1로 고정되어 있고, 통합 Codex 빌드는 내려받은 원본 소스의 toolchain을 사용합니다. |
| 터미널 | UTF-8 표시가 필요합니다. 마우스와 클립보드 기능은 터미널의 지원 여부에 따라 달라집니다. |

소스 빌드와 의존성 다운로드에 필요한 시간과 디스크 공간을 확보하세요. 로컬 소스를 연결하는 `link` 명령은 빌드를 실행하지 않습니다.

Codex 0.162.1 소스는 **Bazel 9.2.0**을 지정합니다. Bazelisk는 이 버전을 자동으로 선택할 수 있으며, 고정 버전의 `bazel` 실행 파일은 같은 버전을 표시해야 합니다. 준비 상태 확인에서는 Bazel 실행 가능 여부를, 소스 빌드 단계에서는 정확한 버전을 확인합니다.

요약에는 **추가 모델 사용량**이 발생하며, **금액 기준 예산 상한은 없습니다**. 기록은 로컬에 저장하지만 요약 대상 대화와 제한된 기존 기록 색인을 Codex를 통해 모델 서비스로 전송합니다. 패널을 숨겨도 수집은 계속됩니다. 수집과 요약을 중지하려면 메뉴의 **이 탭 수집 끄기**를 선택하세요. [저장과 개인정보](#저장과-개인정보)에서 자세히 설명합니다.

## 1. Maeklog 빌드와 연결

**Herdr 일반 셸**에서 소스를 복제하고 빌드한 뒤, 소스 디렉터리를 연결하고 수집 훅을 설치합니다.

```sh
git clone --branch v0.14.0 --single-branch https://github.com/reganpark/maeklog.git
cd maeklog
cargo build --locked --release
maeklog_root="$PWD"
herdr plugin link "$maeklog_root"
herdr plugin action invoke install-codex-hooks --plugin maeklog
```

업데이트 도구가 이 소스의 스크립트와 패치를 사용하므로 설치 후에도 소스 디렉터리를 유지하세요. `maeklog_root`가 유지되도록 4단계까지 같은 셸을 사용합니다. 나중에 다시 진행한다면 실제 소스 디렉터리의 절대 경로로 이 변수를 다시 설정하세요.

위 명령은 **v0.14.0 공개 프리뷰**를 선택합니다. 개발 중인 변경 사항을 작업하려면 `main`을 명시적으로 복제하세요. 릴리스 버전과 내용이 다를 수 있습니다.

훅 설치 동작은 Maeklog 훅 실행 파일과 실행 설정을 만들고, Codex의 `hooks.json`에 핸들러 네 개를 등록합니다. 기존 훅 파일을 변경 전에 백업하고 다른 핸들러는 보존합니다. 훅 신뢰는 부여하지 않습니다.

## 2. Codex 훅 검토와 신뢰

hooks 기능이 꺼져 있다면 셸에서 활성화하고 새 Codex 세션을 엽니다.

```sh
codex features enable hooks
codex
```

**Codex 안에서** `/hooks`를 열어 **Maeklog 핸들러 네 개를 모두 검토하고 신뢰**하세요.

| 이벤트 | 수집 대상 |
| --- | --- |
| `SessionStart` | 세션 연결 |
| `UserPromptSubmit` | 사용자 요청 |
| `Stop` | 최종 답변 |
| `Interrupt` | 중단 사실 |

각 핸들러는 Maeklog 설정 디렉터리의 `bin/maeklog-hook`을 실행하며, 마지막 인자는 `hook`입니다. 소스나 명령이 달라져 신뢰가 유효하지 않으면 `/hooks`에서 새 정의를 다시 검토하세요. 설치 도구는 이 승인을 대신하지 않습니다.

진행 중인 작업을 마치고 Codex를 정상 종료한 뒤 계속 진행하세요.

## 3. 준비 상태 확인

Codex 입력 화면을 나와 앞에서 사용한 **Herdr 일반 셸**로 돌아갑니다.

```sh
python3 "$maeklog_root/scripts/update-codex-maeklog.py" --preflight
```

`--preflight`는 필수 명령, Herdr 실행 환경, 설치된 실행 설정과 훅, hooks 활성화, 현재 핸들러 정의 네 개의 수동 신뢰 상태를 확인합니다. 다운로드·빌드·모델 호출은 하지 않습니다. 오류를 해결한 뒤 다시 실행하세요. `--check`는 버전 정보만 확인하므로 이 준비 상태 확인을 대신하지 않습니다.

`XDG_CONFIG_HOME`이나 `CODEX_HOME`을 바꿔 쓴다면 훅 설치·신뢰·업데이트·Codex 실행에 같은 환경을 유지하세요. 별도 `HERDR_PLUGIN_CONFIG_DIR`가 브릿지 경로인 `$XDG_CONFIG_HOME/herdr/plugins/config/maeklog` 밖을 가리키는 구성은 이 설치 흐름에서 지원하지 않습니다. 경로를 추측하지 않고 준비 상태 확인에서 중단합니다. XDG 설정이 없으면 기본 경로는 `~/.config/herdr/plugins/config/maeklog`입니다.

## 4. 통합 Codex 빌드와 활성화

**Herdr 일반 셸**에서 실행합니다.

```sh
python3 "$maeklog_root/scripts/update-codex-maeklog.py" 0.162.1 --apply
```

업데이트 도구는 공식 Codex 소스와 버전이 일치하는 helper/resource 패키지를 내려받고, Maeklog 패치를 적용해 빌드·검증한 뒤 런처를 연결합니다. 검증은 로컬 응답 fixture와 임시 Herdr 분할 창(pane)을 사용하며 외부 모델을 호출하지 않습니다. 준비 상태 확인이나 검증이 실패하면 활성 설치를 교체하지 않습니다.

설치를 활성화하지 않고 빌드·검증만 하려면 `--apply`를 생략하세요. 생략해도 다운로드·빌드·검증은 진행합니다.

```sh
python3 "$maeklog_root/scripts/update-codex-maeklog.py" 0.162.1
```

활성화할 때 기존 실행 파일·런처·설정을 백업합니다. 이전 Herdr 서버 측 `SessionStart` 핸들러가 있다면 확인된 해당 핸들러만 비활성화하고 Maeklog 터미널 클라이언트의 보고를 사용합니다. 실행 중인 Codex 프로세스나 공유 Herdr 서버는 재시작하지 않습니다.

### 새 셸에서 런처 확인

**새 Herdr 일반 셸**을 열고 PATH 맨 앞에 `~/.local/bin`을 둡니다.

```sh
export PATH="$HOME/.local/bin:$PATH"
command -v codex
command -v codex-maeklog
codex --version
codex-maeklog --version
```

경로는 각각 `~/.local/bin/codex`, `~/.local/bin/codex-maeklog`이며, 두 버전 출력은 `codex-cli 0.162.1`이어야 합니다. 공식 CLI도 같은 버전을 표시하므로 경로, 준비 상태 확인 결과, 아래의 첫 대화까지 함께 확인하세요.

PATH 변경은 현재 셸에 적용됩니다. 계속 사용하려면 셸 시작 파일에 같은 `export` 줄을 추가하세요. Bash는 `~/.bashrc`, Zsh는 `~/.zshrc`를 사용하며, 로그인 셸 등 별도 구성이 있다면 그 설정을 따릅니다. 셸이 이전 실행 파일을 기억한다면 새 터미널을 열거나 명령 캐시를 새로고침하세요.

`codex-maeklog`는 패키지 경로·버전 확인용 포인터입니다. **대화형 작업은 설치된 `codex` 런처로 실행하세요.** PATH가 다른 명령을 선택하면 `~/.local/bin/codex`를 직접 실행합니다. 이 파일 자체가 덮어써졌다면 설치된 런처 스크립트를 사용하세요.

```sh
python3 "$HOME/.local/share/maeklog/codex-launcher.py"
# 같은 대화 재개:
python3 "$HOME/.local/share/maeklog/codex-launcher.py" resume
```

이미 실행 중인 Codex 프로세스는 기존 코드를 유지합니다. 작업을 마치고 정상 종료한 뒤 새 런처로 대화를 재개하세요.

## 5. 첫 대화 확인

프로젝트 탭의 Herdr 일반 셸에서 패널을 엽니다.

```sh
herdr plugin action invoke open --plugin maeklog
```

같은 셸에서 `codex` 또는 `codex resume`을 실행하고 민감한 정보가 없는 짧은 요청을 주고받으세요. 응답이 끝나면 추가 요약 사용량이 발생할 수 있습니다.

현재 진행 영역에서 공개 설명을 확인한 뒤, 응답이 끝나면 저장 기록의 반영 상태를 확인합니다. 공개 설명이 없는 응답은 **진행 정보 없음**으로 표시될 수 있습니다. 확정된 결정이나 완료 보고가 없는 턴도 있으므로 새 기록이 항상 생기지는 않습니다.

패널을 클릭해 포커스를 둡니다. `h`로 기록을 열람하고, 항목이 있으면 `e`로 근거를 확인하세요. 오늘 완료 대화가 아직 반영되지 않았다면 `r`을 사용합니다.

이전 대화나 수집을 꺼둔 동안의 대화는 **자동으로 가져오지 않습니다**. 응답 종료가 작업 완료를 뜻하지는 않습니다.

## 설정

`m`, `F10` 또는 우클릭으로 패널 메뉴를 엽니다.

- **요약 모델…:** 모델과 지원하는 추론 강도를 선택합니다. 기본값은 `gpt-6-luna`, 추론 강도 `medium`, Standard 서비스입니다.
- **언어 / Language…:** 자동 / Auto, English, 한국어 중 선택합니다. 기존 기록을 다시 번역하지 않으며 원문 인용은 원래 언어를 유지합니다.
- **이슈·PR 연결:** 현재 대화의 참조를 확인합니다. `l`로 연결을 정정하고 `o`로 링크를 엽니다.

모델이나 언어 설정을 바꿔도 요약을 실행하거나 기존 기록을 다시 쓰지 않습니다. 변경은 이후 요약에 적용됩니다. 완료 대화 요약과 `r`, `b`, `s` 요청에는 추가 모델 사용량이 발생할 수 있습니다. 모델·언어 설정은 같은 Maeklog 설정 디렉터리를 사용하는 탭에 적용됩니다.

### 열기·숨기기 단축키 설정 (선택)

`open` 동작을 확인한 뒤 Herdr 키 설정에 아래 항목을 추가하세요. 기본 파일은 `~/.config/herdr/config.toml`이며 `HERDR_CONFIG_PATH`로 바꿀 수 있습니다. 실제 경로는 `herdr --help`의 `Config` 항목에서 확인합니다. 같은 키가 이미 있다면 중복 항목을 추가하지 말고 기존 항목을 수정하세요.

```toml
[[keys.command]]
key = "prefix+m"
type = "plugin_action"
command = "maeklog.open"
description = "open Maeklog"

[[keys.command]]
key = "prefix+shift+m"
type = "plugin_action"
command = "maeklog.hide"
description = "hide Maeklog"
```

설정을 확인하고 적용합니다.

```sh
herdr config check
herdr server reload-config
```

기본 prefix는 `Ctrl+B`입니다. `Ctrl+B`를 누른 뒤 `m`을 누르면 열리고, `Ctrl+B` 뒤 대문자 `M`을 누르면 숨겨집니다. Herdr에서 prefix를 바꿨다면 자신의 설정을 사용하세요.

## 일상 조작

키를 사용하기 전에 패널을 클릭해 포커스를 둡니다. 모든 동작은 메뉴에서도 찾을 수 있습니다.

| 입력 | 동작 |
| --- | --- |
| `h` | 모델 호출 없이 전체 저장 기록을 읽습니다. |
| `e` | 근거를 확인하고, 기록을 정정·제외하거나 정정을 되돌립니다. |
| `r` | 오늘의 미처리 완료 대화를 요약하거나 실패한 작업을 재시도합니다. |
| `b` | 이전 날짜나 보류된 날짜를 선택하고 `Enter`로 요약을 요청합니다. 선택 화면만 열 때는 모델을 호출하지 않습니다. |
| `s` | 현재 공개 진행의 잠정 요약을 요청합니다. |
| `l` / `o` | 이슈·PR 연결을 정정하거나 연결된 참조를 엽니다. |
| `v` | 요약 요청 없이 이슈·PR 정보를 새로고침합니다. |
| `q` | 패널을 숨깁니다. 수집은 계속됩니다. |
| 방향키, `j`/`k`, 마우스 휠 | 스크롤합니다. |

오늘 수집된 완료 대화는 최신 묶음부터 자동 요약합니다. 이전 날짜, 시각을 알 수 없는 대화, 자정을 넘긴 대화는 `b`에서 선택해야 합니다. 같은 작업은 최대 세 번 자동 시도하고, 이후에는 명시적 재시도를 위해 원문을 보존합니다.

패널을 숨겨도 수집은 계속됩니다. 수집과 요약을 중지하려면 메뉴의 **이 탭 수집 끄기**를 사용하세요. 수집을 껐던 탭에서 패널을 다시 열거나 수집을 재개하면 오늘 수집된 완료 대화 중 최근 최대 3턴을 처리하고, 나머지는 `b`에서 수동 선택하도록 보류합니다. 다른 탭은 각자의 수집 설정을 유지합니다. [날짜·재시도·수집 범위](usage.md#언제-자동으로-요약하나요)에서 자세히 설명합니다.

## 기록으로 알 수 있는 것

Maeklog는 수집한 Codex 대화를 정리해 작업 맥락을 다시 파악하도록 돕습니다. 저장 기록을 Codex의 기억으로 자동 주입하지는 않습니다. 이 가이드의 통합은 Codex를 지원하며, 임의의 다른 에이전트를 지원하는 방식은 아닙니다.

완료 기록은 구현·검증·병합·배포 보고를 구분합니다. 이 기록은 대화에서 나온 보고이며, Maeklog가 작업을 독립적으로 검증하거나 승인하거나 다음 행동을 실행하지는 않습니다. 결정·완료 보고는 변경 이력을 보존하고, 다음 행동은 담당자와 조건을 유지합니다. `e`로 근거를 확인하고 오류를 정정하세요.

공개 설명·계획·활동과 기록된 진행·막힘·다음 행동을 함께 표시합니다. 기록은 로컬에 저장하며 팀 클라우드 동기화는 제공하지 않습니다.

## 저장과 개인정보

실제 기록 디렉터리는 Maeklog 설정 디렉터리의 `hook-runtime.json`에 있는 `state_dir` 값입니다. Herdr 플러그인의 기본 상태 경로는 `~/.local/state/herdr/plugins/maeklog`, 기본 설정 경로는 `~/.config/herdr/plugins/config/maeklog`입니다. XDG 경로나 명시적 설정에 따라 달라질 수 있습니다.

디렉터리는 `0700`, 파일은 `0600` 권한을 사용합니다. 저장소는 **암호화되지 않습니다**. 대기 원문, 근거 인용, 진단 파일에는 민감한 대화가 포함될 수 있습니다.

완료 대화에서는 사용자 요청·최종 답변·중단 사실·세션 연결을 수집합니다. 현재 진행 캐시는 공개 설명·계획·도구 활동 메타데이터를 별도로 저장합니다. 비공개 추론과 도구 출력 본문은 수집하지 않습니다. 요약할 때는 선택한 대화와 제한된 기존 기록 색인을 Codex를 통해 모델 서비스로 전송하며, 전체 원장을 전송하지는 않습니다.

요약에는 추가 모델 사용량이 발생하며 금액 기준 예산 상한은 없습니다. 공개 진행 표시, 저장 기록 열람, 설정 변경만으로는 요약을 실행하지 않습니다. 모델의 해석이 틀릴 수 있으므로 중요한 기록은 `e`로 근거를 확인하고 정정하세요.

[저장과 삭제](usage.md#모델-사용량과-저장), [보안 정책](../SECURITY.md)도 참고하세요.

## 업데이트

Herdr 일반 셸에서 실행합니다.

```sh
codex update --check
codex update 0.162.1
```

`codex update`는 Maeklog의 검증된 업데이트 흐름을 사용합니다. 패치가 새 원본 소스와 맞지 않거나 검증이 실패하면 설치를 중단합니다. 일반 npm 업데이트는 이 통합을 업데이트하지 않으며 실행할 `codex` 런처가 바뀔 수 있습니다. 소스 디렉터리를 유지하고 [Codex 통합·업데이트 가이드](../integrations/codex/README.md)를 확인하세요.

## 문제 해결

| 증상 | 먼저 확인할 사항 |
| --- | --- |
| Python에서 `tomllib`을 찾을 수 없음 | Python 3.11 이상을 사용하세요. |
| 필수 명령이나 Bazel이 없음 | 준비 상태 확인에서 표시한 도구를 설치하세요. Bazelisk는 PATH에 `bazel` 명령을 제공해야 합니다. |
| Maeklog가 없거나 설치가 여러 개 표시됨 | `herdr plugin list --plugin maeklog --json`에서 플러그인 ID와 실제 경로를 확인하세요. 설치·연결 상태를 정리하고 경로를 추측하지 마세요. |
| Maeklog 바이너리가 없음 | release 빌드 결과를 확인하세요. Herdr가 관리하는 빌드는 `herdr plugin log list --plugin maeklog`로 확인합니다. |
| 훅이 없거나 신뢰가 맞지 않음 | `install-codex-hooks`를 실행하고 같은 Codex 환경의 `/hooks`에서 현재 정의 네 개를 모두 검토·신뢰한 뒤 `--preflight`를 다시 실행하세요. |
| 패널은 열리지만 새 대화가 보이지 않음 | 새 터미널이 통합 `codex` 런처를 사용하는지 확인하고, `/hooks`에서 핸들러 네 개를 검토한 뒤 `--preflight`를 다시 실행하세요. |
| 오늘 기록이 아직 반영되지 않음 | Codex 응답이 끝날 때까지 기다린 뒤 `r`을 누르세요. 이전 대화나 보류된 대화는 `b`를 사용합니다. |
| 요약 처리 실패 또는 자동 재시도 중지 | `h`로 요약·처리 상세를 열어 모델 접근 권한·네트워크·설정을 확인하세요. 원인을 해결한 뒤 오늘은 `r`, 이전 날짜는 `b`에서 다시 선택합니다. |
| 같은 대화를 두 터미널에서 열었더니 수집이 멈춤 | 요청을 제출한 터미널이 모호하면 새 입력을 보류합니다. 한 터미널에서 계속 진행하세요. |
| 드래그해도 클립보드에 복사되지 않음 | OSC 52 지원 여부를 확인하거나 Herdr의 `prefix+[` 복사 모드를 사용하세요. |

[기존 설치 안내의 문제 해결](getting-started.md#문제-해결)에서 다른 설치 오류를 확인할 수 있습니다. 현재 동작은 [사용 안내](usage.md)를 참고하세요.
