# 탭별 Maeklog 패널과 맥락 — v0.14.0

각 탭에서 `prefix + m`을 누르면 그 탭에 Maeklog 패널이 열립니다. 다른 탭에 Maeklog이 열려 있어도 방해하지 않습니다. 같은 탭에서 다시 열면 기존 패널을 재사용합니다. 포커스는 작업 창에 유지합니다.

## 무엇이 분리되나요?

수집 대기열, 연결된 Codex 세션, 오늘/과거 날짜별 처리, 요약 재시도, 패널 열림/숨김, Maeklog 켜짐/꺼짐이 탭별입니다. 저장된 결정·완료·진행·막힘·다음 행동과 브랜치에서 찾은 이슈/PR은 **탭 + 저장소 + 브랜치** 단위로 분리합니다. 같은 `main` 브랜치를 사용하는 두 탭의 대화도 섞지 않습니다. 한 탭에서 새 Codex 세션을 시작해도 그 탭의 기존 기록은 유지합니다.

상단의 **현재 대화의 작업**은 그 탭에 연결된 Codex 대화별로 저장합니다. 브랜치를 바꾸거나 PR이 병합되어도 현재 작업 참조를 유지합니다. 새 대화는 빈 연결로 시작하고, 이전 대화를 재개하면 그 대화의 참조를 복원합니다. `l`의 연결 정정은 이 카드에 적용되며, 아래의 **저장된 브랜치 기록**을 옮기거나 다시 쓰지 않습니다. 작업 보고의 연결·검증 방식은 [Codex 작업 참조 인계](../integrations/codex/task-reports.md)에 설명되어 있습니다.

`e`의 근거 보기와 사용자 정정은 해당 탭의 현재 브랜치 기록에 적용됩니다. 다른 탭으로 정정을 전파하지 않습니다. 저장 확인 화면에도 이 범위를 표시합니다. 브랜치 전환 전후 기록은 여전히 분리합니다.

## 기존 Space 기록

기존 기록에는 탭 식별자가 없어 자동으로 특정 탭에 배정하지 않습니다. 기존 Space 파일과 공용 브랜치 원장은 그대로 보관하고, 새 탭 대기열·모델 입력·기본 화면에 섞지 않습니다. 탭별 수집이 생긴 Space의 이전 혼합 대기열은 자동 요약 대상에서 제외합니다. 새 탭에는 업데이트 이후 해당 탭에서 수집한 대화부터 표시됩니다. 이전 전체 대화를 몰래 재수집하거나 재요약하지 않습니다.

이전 기록은 기존 `memory list`, `memory show KEY`, `memory history KEY`로 조회할 수 있습니다. 새 `tab-branch-…` 항목에는 `tab_id`가 포함됩니다. Space 설정을 꺼두었던 경우 새 탭도 꺼진 설정을 상속하며, 명시적으로 패널을 열어 그 탭만 다시 켤 수 있습니다.

## 경계와 복구

- 실제 호출 pane의 현재 tab/workspace가 상속 환경변수보다 우선합니다. pane을 다른 탭으로 옮겼다면 이후 대화는 이동한 탭으로 수집합니다. 이미 저장된 과거 대화의 귀속은 바꾸지 않습니다.
- 탭을 식별할 수 없는 훅은 다른 탭의 포커스를 추측해 수집하지 않습니다. 탭 정보 없는 이전 방식의 저장 경로를 유지하되, 탭 분리 후에는 해당 혼합 대기열을 자동 처리하지 않습니다.
- 숨기기는 그 탭의 수집을 유지하며, 끄기는 그 탭의 수집/요약을 중지합니다. Space 전체가 닫히면 그 Space의 모든 탭 저장소를 보관 상태로 둡니다.
- 재시작에서는 이미 알려진 열린 패널만 같은 탭에 복원합니다. 닫힌 탭의 패널을 다른 탭에 임의로 생성하지 않습니다.
- 전체 동시 모델 작업 한도 3개, 저장 범위당 한 작업, 재시도/오늘 자동 정책은 유지합니다.
