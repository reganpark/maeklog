# Maeklog 사용 안내

[설치와 최초 확인](getting-started.md)을 마친 뒤 화면을 읽고 설정을 바꾸는 방법입니다. 기본 화면은 현재 대화의 공개 진행과 이 탭에 저장한 기록을 함께 보여줍니다. 완료 항목은 대화에서 보고한 사실이며, 중요한 결정과 완료는 `e`로 근거를 확인하세요.

아래 CLI 예시의 `$maeklog_root`는 설치 안내에서 확인한 Maeklog 플러그인 경로입니다. 일반적인 사용은 패널 메뉴로 할 수 있습니다.

## 화면과 조작

기본 화면은 **현재 대화의 작업·공개 진행**을 먼저, **이 탭의 저장 기록 · 브랜치**를 그 아래에 표시합니다. 최근 요청은 보조 정보이며 작업 제목으로 바꾸지 않습니다. 공개 진행이 없으면 ‘진행 정보 없음’이고, 응답 종료·요약 큐 0을 작업 완료로 판단하지 않습니다.

작업 미연결·참고 후보·`l` 안내는 한 묶음으로 표시합니다. 한 줄 간격 뒤에 진행 설명의 시각과 응답 상태를 제목으로 묶고, 본문 문단은 두 칸 들여씁니다. 설명 시각과 응답 상태를 본문 아래에 반복하지 않습니다.

최신 공개 진행 설명과 저장된 유효 결정·오늘 완료·기록된 진행·막힘·다음 행동을 기본 화면에서 끝까지 읽을 수 있습니다. 길면 줄바꿈하고 스크롤하며, 항목 수나 본문 길이로 잘라내지 않습니다. 기록마다 시각·보고 유형 또는 담당·본문을 한 묶음으로 표시하고 조건도 유지합니다. 마지막 반영·미반영·수집 공백은 저장 기록의 상태 안내 한 곳에 모읍니다. 이전 날짜·변경 이력은 `h`에서 읽으며 저장 내용과 항목 시각을 다시 쓰거나 요약하지 않습니다.

내용 영역을 왼쪽 드래그하면 반전색으로 선택되고 마우스를 놓으면 OSC 52로 복사를 요청합니다(최대 64 KiB, 터미널/Herdr의 클립보드 지원 필요). 선택 중에는 화면 내용과 줄 위치가 고정되며 수집·요약은 계속됩니다. Esc는 먼저 선택만 해제하며, 스크롤·크기 변경·다른 키 입력도 선택을 해제합니다. 우클릭 메뉴와 휠은 유지합니다. 복사 범위는 현재 화면 안이며 줄바꿈은 표시된 행 기준입니다. 선택이 끝난 뒤 자동으로 화면 갱신에 복귀하려면 Esc를 누르세요. 클립보드 수신 성공을 독립 확인하지 않으므로 하단은 ‘복사 요청’으로 표시합니다. 터미널이 OSC 52를 막으면 Herdr의 `prefix + [` 복사 모드를 사용할 수 있습니다.

Gruvbox Dark에서 두 주요 구획은 굵은 제목과 구분선, 항목 범주는 굵은 제목으로 구별합니다. 본문·시각·보조 안내 모두 밝은 중립색이며 회색이나 흐리게 처리한 글자를 사용하지 않습니다. 검증된 참조는 청록색, 실제 주의·실패는 주황색 또는 빨강, 선택은 노란색으로 구별합니다. 확인 안 됨을 ‘없음’이나 성공으로 단정하지 않습니다. 색은 화면 전용이며 저장 내용·모델 입력·텍스트 내보내기에 포함되지 않습니다.


`NO_COLOR` 환경변수가 설정된 실행 환경에서는 색상을 생략하며 굵기·제목·선택 화살표는 유지합니다. `render-once`와 `memory`의 텍스트 출력에는 ANSI 색상 코드를 넣지 않습니다.

하단에는 현재 보이는 행 범위·전체 행 수와 `↓ 아래 내용` 안내, `r 반영 · l 연결 · e 근거 · h 기록 · m 메뉴`를 표시합니다. 실제 글자 폭에 맞춰 안내를 줄이며, 좁은 화면에서도 `r 반영`을 우선 유지합니다. 나머지 동작도 메뉴에서 찾을 수 있습니다. 정상 요약 큐 0은 기본 화면을 차지하지 않고 전체 기록의 범위·수집 상세에서 확인합니다. 요약 실패·재시도 대기·미반영과 명시적으로 요청한 날짜의 처리 상태는 기록 범위에 표시합니다.

`h`는 **전체 기록 열람**을 엽니다. 오늘 완료, 유효 결정, 기록된 진행·막힘·행동, 이전 기록, 정정으로 제외된 기록, 구버전·미연결 기록, 변경·근거, 범위·수집 상세, 기록 요약·처리 상세를 범주별로 읽습니다. 열람 시점의 내용과 범위가 고정되며 `Esc`로 원래 기본 화면의 스크롤 위치에 돌아옵니다. `m`의 **진행 상황 보기**에는 캐시에 보존된 공개 설명·계획·활동과 최근 요청 전체가 있습니다. 공개 설명이 아직 없을 때는 최근 요청 전체를 기본 화면에도 표시합니다. 수집 단계에서 이미 생략된 내용은 생략 안내를 유지합니다. 저장된 근거와 정정은 기존 `e`를 사용합니다.

| 입력 | 동작 |
| --- | --- |
| prefix + m | 패널 열기. 수집을 꺼둔 탭이라면 아래 최근 3턴 규칙으로 재활성화 |
| s | 현재 공개 진행 기록으로 잠정 요약 요청. 같은 기록·모델·강도·언어이면 캐시 재사용 |
| b | 이전/보류 날짜 선택 열기. 모델 호출 없이 선택 화면 열기 |
| 날짜 선택에서 ↑↓ / Enter | 날짜 선택 / 그 날짜의 현재 대기 대화만 요약 실행 |
| 날짜 선택에서 Esc | 실행 없이 취소 |
| e | 항목 선택 → Enter 근거 보기 → e 내용·조건 정정 / x 오기록 제외 / u 되돌리기 |
| h | 전체 기록의 고정된 내용 열람. 모델·GitHub 호출 없음 |
| l / o | 작업 연결 정정 화면 / 현재 연결의 링크 열기 |
| v | 작업 참조를 백그라운드에서 다시 확인 |
| 조회 화면에서 ←→ / [ / ] | 이전/다음 범주. ↑↓·j/k·PgUp/PgDn·Home/End로 읽기 |
| 조회 화면에서 Esc / h / q | 조회 화면만 닫고 기본 화면의 원래 스크롤 위치로 복귀 |
| r | 수집된 오늘 미반영 완료 대화 반영·실패 재시도. 대상 없음·응답 대기는 별도 안내 |
| 우클릭 / m | Maeklog 메뉴 열기 |
| j/k, 방향키, 휠, Home/End | 스크롤 |
| q / 메뉴가 닫힌 상태의 Esc | 패널만 숨기기. 수집은 계속 |

우클릭·`m`·`F10`은 같은 Maeklog 메뉴를 엽니다. 첫 선택은 조회 전용 **저장 기록 보기**, 두 번째는 **요약 모델…**, 세 번째는 **언어 / Language…**, 네 번째는 **진행 상황 보기**입니다. 동작 이름과 오른쪽 단축키 열을 나눠 표시하며 메뉴가 열린 상태에서도 `h`·`l`·`e`·`o`·`s`·`b`·`r`·`v`·`q`가 해당 동작을 실행합니다. 모델·언어·진행 보기에는 별도 단축키를 추가하지 않고 화살표와 `Enter`로 선택합니다. `q`는 패널 숨기기, `Esc`는 메뉴만 닫기입니다. 하단에는 `↑↓ 이동 · Enter 선택 · Esc 닫기` 안내를 표시합니다. 조회 화면에서는 `s`·`r`·`v`·`Enter`로 요약이나 확인을 요청하지 않습니다. Maeklog 내용 영역의 메뉴이며 Herdr 제목줄·테두리의 Close pane 메뉴와는 다릅니다.

날짜 선택이 열려 있는 동안 `m`·`F10`·우클릭은 다른 메뉴를 열지 않습니다. `Esc`로 취소하거나 날짜를 선택하고 `Enter`를 눌러야 기본 화면으로 돌아옵니다. 날짜를 선택하고 Enter를 눌러야 과거 요약이 시작됩니다. 그 시점의 해당 날짜 이벤트 ID를 고정하므로 나중에 추가된 과거 원문까지 몰래 포함하지 않습니다. 수동 요청은 다음 처리부터 우선하며, 이미 실행 중인 작업은 기존 허용 범위 내에서 마무리됩니다. Space를 끄면 수동 요청도 무효화됩니다. r은 남은 수동 요청을 해제하고 오늘 재시도를 요청합니다.

`r`은 **미반영 완료 대화를 실제로 반영하는 키**이며 기록을 읽고 재확인만 하는 동작이 아닙니다. 오늘 반영할 완료 대화가 없으면 worker를 새로 시작하지 않고, 완료 응답을 기다리는 기록이나 `b`로 선택할 이전/보류 대화가 있는지 안내합니다. ‘반영 요청’은 처리가 끝났다는 뜻이 아닙니다. ‘마지막 반영’은 반영된 원문의 시각이며 `r`을 눌렀다는 이유로 현재 시각으로 바꾸지 않습니다.

전체 과거를 수집하지 않은 정상적인 범위 제한은 `h`의 수집 상세에 안내합니다. 이 상태를 현재 ‘수집 공백’ 경고로 표시하지 않습니다. 실제 수집 중단 근거는 **과거 수집 공백**으로 보존하며, `r`이 이 근거를 지우거나 수집하지 않은 과거를 자동 복원하지 않습니다.

### 진행 화면과 `s`의 잠정 요약

공개 설명·계획·활동을 표시하는 것 자체에는 추가 모델 호출이 없습니다. 기본 화면은 최근 공개 설명을 먼저 보여 주고, 메뉴의 **진행 상황 보기**에서 수집해 둔 설명·계획·활동과 최근 요청을 읽을 수 있습니다. 비공개 추론과 도구 출력 본문은 이 캐시에 넣지 않습니다.

`s`를 누르면 그 시점의 공개 기록을 고정해 한 번 요약 요청합니다. 요청한 뒤 들어오는 새 활동은 자동으로 입력에 추가하지 않고 화면에서 미반영으로 구분합니다. 같은 기록·모델·추론 강도·실제 언어의 준비된 결과는 재사용합니다. 완료 대화 처리와 동시 작업 제한을 공유하며, 잠정 요약 요청에는 추가 모델 사용량이 발생합니다.

진행 요약이 실패하면 자동으로 계속 재호출하지 않습니다. 원인을 확인한 뒤 `s`로 다시 요청합니다. 최종 답변이 들어오면 진행 중 잠정 요약을 취소하고 완료 대화 요약 흐름을 사용합니다. 잠정 요약은 결정·완료 원장에 확정 기록으로 넣지 않습니다.

## 결정·완료와 현재 상황은 다릅니다

결정마다 `decision_basis`에 발언 유형과 명시적 확정/승인 인용을 지정합니다. 코드가 `?`, ‘제안’ 등의 단어만으로 의도를 판정하지 않습니다. 명시적 선택·승인·조건부 승인만 결정으로 허용하며 질문·누락 지적·작업 요청은 그 자체로 확정 결정이 아닙니다. 필요한 경우 모델이 현재 요청/다음 행동으로 작성하도록 안내합니다. 조건부 승인에는 조건이 필수이고, 근거는 첫 사용자 증거의 정확한 부분 문자열이어야 합니다. 기존 저장 결정에는 근거를 추정해서 채우지 않습니다. 발언 유형을 모델이 잘못 분류하면 코드만으로 의미적 오류를 모두 잡을 수는 없습니다.

같은 처리 작업의 검증 오류는 기존 재시도 프롬프트에 최대 500자로 전달합니다. 다른 작업/Space에 피드백을 옮기지 않습니다. 동일한 제한된 오류 문자열이 두 번 연속 나오면 원문을 남긴 채 자동 재시도를 중단하고 r/b 안내를 표시합니다. 일반 오류는 기존 최대 3회 한도를 유지합니다. 별도 보정 호출이나 잘못된 항목의 부분 저장은 하지 않습니다.

결정·완료는 누적 기록이고, 진행·막힘·다음 행동은 현재 상태 요약입니다.

- 현재 유효한 결정은 최신순으로 모두 표시합니다. 제안·질문은 확정 결정으로 등록하지 않습니다.
- 오늘 완료는 기본 화면에서 모두 스크롤해 읽으며 `h`에는 이전 날짜·시각 미확인 기록도 보존됩니다. **화면 표시와 요약 입력 턴 수는 별개**입니다.
- 결정 변경·철회는 이전 항목과 시각을 연결합니다. 구현이 끝나도 그 결정은 지우지 않습니다.
- 완료 뒤 실패·재작업·재검증 보고를 원래 완료에 연결합니다. 이전 날짜의 해결되지 않은 실패도 기본 화면에 경고와 본문을 유지합니다.
- 모든 완료는 **보고로 표시**합니다. 구현 완료·검증 통과·병합·배포를 구별하며 Maeklog의 독립 검증·승인처럼 표현하지 않습니다.
- 막힘의 언급이 사라졌다는 이유로 해제하지 않습니다. 현재 상태 미확인으로 유지하고 명시적인 해제 근거가 있어야 현재 목록에서 제외합니다.
- 다음 행동은 담당 주체와 승인·검증 조건을 유지합니다. 좁은 패널에서도 중요한 조건은 잘라내지 않고 줄바꿈합니다.

새 요약, 재시작, Space·세션·브랜치 변경, 패널 접기, 날짜 변경만으로 결정·완료를 삭제하지 않습니다. 저장된 기록에는 자동 만료나 보관 건수 제한이 없습니다.


## 시각과 중복 처리

항목 시각은 모델이 만든 날짜가 아닙니다. 첫 근거 event:N과 정확한 원문 인용을 코드에서 검사하고, 저장된 원본 이벤트 시각에 연결합니다. 결정의 주 근거는 사용자 발언이어야 합니다.

UTC epoch 초(*_unix_utc)로 저장하고 연도·날짜·시각을 사용자 로컬 시간대로 표시합니다(예: `2026/09/14 14:30`). `+0900` 같은 UTC 오프셋은 화면에서 생략하며 저장값과 시간대 변환은 유지합니다. 원본 시각이 없으면 ‘시각 미확인’이며 현재 시각·파일 mtime·이관 시각으로 채우지 않습니다.

동일 상태 반복과 표현 수정에는 원래 시각과 그 근거를 유지합니다. 실질적 변경에만 새 근거 시각을 붙입니다. 항목별 시각, 대화 반영 시각, 요약 저장 시각, GitHub 조회 시각은 서로 다릅니다.

이벤트 ID, 의미 키, 출처, 버전과 변경 관계를 보존합니다. 이미 누적 처리한 이벤트는 처리 지문으로 고정하므로 재시도에서 다른 키·인용으로 표현해도 새 항목을 만들지 않습니다. 최초 처리에서 놓친 의미를 같은 이벤트 재요약으로 자동 보충하는 기능은 아닙니다.

최신 묶음을 먼저 처리해도 큰 sequence 번호까지 통째로 삭제하지 않습니다. selected-current.json에 정확한 처리 ID와 상태를 원자적으로 저장하고, 선택한 원문만 제거합니다. 오래된 결과는 최신 현재 상태·Space 요약·결정 변경 관계를 덮어쓰지 못합니다. 완료의 이전 근거가 나중에 처리돼도 근거 순서에 맞춰 후속 관계를 연결할 수 있습니다.

새 요약에서는 ‘최신 미리보기 → 같은 이벤트 누적 처리’의 중복 호출을 만들지 않고, 최신 대화를 바로 누적 처리합니다. 예전 latest.json은 호환 자료로 읽을 수 있지만 새 처리 상태가 생기면 그 화면을 사용하지 않습니다.


## 언제 자동으로 요약하나요?

**이미 수집된 오늘의 미요약 완료 대화만, 최신 묶음부터 자동 처리합니다.** 전체 과거를 최신순으로 싹 따라잡는 동작이 아닙니다.

| 대화 | 처리 |
| --- | --- |
| 오늘의 미요약 완료 대화 | 자동, 최신 완료 묶음 우선 |
| 이전 날짜의 미요약 대화 | 보존 후 사용자 요청 대기. 자동 호출 없음 |
| 원본 시각 미확인 / 자정을 걸친 대화 | 별도 수동 선택 대상 |
| 아직 끝나지 않은 대화 | 완료 대기 |
| 이미 처리한 이벤트·저장된 결정/완료 | 재요약하지 않고 기존 기록 표시 |
| 같은 작업의 요약 실패 | 최대 3회, 이후 명시적 재시도 대기 |

오늘은 사용자 로컬 시간대(TZ 또는 시스템 시간대)의 자정 기준입니다. 한 완료 턴에 포함된 원본 이벤트가 모두 오늘이어야 자동 대상입니다. 자정이 지나면 남은 오늘 기록은 이전 날짜로 바뀝니다. 진행 중 자동 모델 프로세스도 날짜 경계에서 중단을 시도하고, 미완료 결과를 확정 저장하지 않습니다. 이미 전송한 요청이나 발생한 사용량을 회수하지는 못합니다.

**수집하지 않은 과거까지 자동 복원하지 않습니다.** 날짜 선택은 Maeklog 대기열에 실제로 수집되어 있는 원문을 대상으로 합니다.


## 끄기와 다시 켜기

메뉴의 **이 탭 수집 끄기**를 선택하면 이 탭의 수집과 요약을 중지합니다. **패널 숨기기**나 `q`는 화면만 닫고 수집을 계속합니다.

끄기는 탭별입니다. 다른 탭이 같은 브랜치를 사용해도 꺼둔 탭이 자동 활성화되지 않습니다. 포커스 이동·시작·세션 연결만으로 재활성화하지 않습니다.

명시적으로 다시 켜면 **수집된 오늘의 완료 대화 중 최근 최대 3턴**을 자동 대상으로 둡니다. 나머지 오늘 대화는 같은 날짜의 수동 보류로, 이전 날짜 대화는 날짜별 수동 대기로 남깁니다. 삭제하지 않고 b에서 선택할 수 있습니다. 이후 새로 수집되는 오늘 대화는 정상 자동 처리합니다.

대화가 없으면 모델 호출 없이 기다립니다. 꺼둔 동안 수집하지 않은 Codex 원본을 자동으로 다시 읽지 않습니다. 이전 기록을 보여주는 것과 생략된 원문을 다시 수집하는 것은 다릅니다.

재활성화 시작 자료의 모델 입력은 이벤트당 최대 2,400자·묶음 합계 최대 14,400자로 제한합니다. 원문 파일을 미리 잘라 덮어쓰지는 않습니다. 일반 신규 대화에는 기존 일반 배치 한도를 적용합니다.

이미 저장한 결정·완료는 그대로이며, 수집 공백은 마지막 확인 기록으로 표시합니다. 패널에 표시되는 다음 행동은 여전히 실행 권한이 아닙니다.


## 언어 설정과 시스템 로캘

`m`·`F10`·우클릭 메뉴에서 **언어 / Language…**를 열고 **자동 / Auto**(기본값), **English**, **한국어** 중 고릅니다. `↑↓`로 이동하고 `Enter` 또는 항목 클릭으로 저장하며 `Esc`는 저장 없이 닫습니다. 선택만 이동할 때는 언어가 바뀌지 않습니다. 언어 설정은 같은 Maeklog 설정 디렉터리를 쓰는 탭에 적용되고, 저장하면 현재 화면에 즉시 반영되며 다른 열린 패널도 다음 설정 확인 때 갱신됩니다(약 1초).

기본 파일은 `$XDG_CONFIG_HOME/herdr/plugins/config/maeklog/language-settings.json` 또는 `$HOME/.config/herdr/plugins/config/maeklog/language-settings.json`입니다. 모델 설정과 같은 명시적 `HERDR_PLUGIN_CONFIG_DIR`·설치 훅·기본 Herdr 경로 규칙을 사용하며, Codex의 일반 언어·모델 설정은 바꾸지 않습니다. 설정 파일이 없으면 Auto입니다. 손상된 파일·유효하지 않은 경로·저장 실패는 기존 파일과 마지막 화면 언어를 유지하고 오류를 알립니다.

Auto는 터미널 프로세스에 전달된 `LC_ALL` → `LC_MESSAGES` → `LANG` 순서로 첫 번째 비어 있지 않은 로캘을 읽습니다. `ko`, `ko_KR.UTF-8`, `ko-KR` 같은 한국어 로캘은 한국어, 영어·미지원 로캘·`C`·`POSIX`·모두 미설정인 환경은 영어를 사용합니다. 예를 들어 `LC_ALL=C`이면 `LANG=ko_KR.UTF-8`보다 우선합니다. English와 한국어 선택은 이 자동 판단 대신 해당 언어를 사용합니다.

Auto의 시스템 로캘 값은 프로세스에서 처음 확인한 값을 유지합니다. 터미널 로캘을 변경한 뒤 Auto에 반영하려면 해당 프로세스를 다시 시작하세요. 데스크톱의 별도 언어 환경설정이나 `LANGUAGE` 값은 macOS에서도 별도로 조회하지 않습니다.

```sh
"$maeklog_root/target/release/maeklog" language show
"$maeklog_root/target/release/maeklog" language set auto
"$maeklog_root/target/release/maeklog" language set en
"$maeklog_root/target/release/maeklog" language set ko
```

언어 설정을 저장하는 동작은 요약을 실행하지 않습니다. 사용자 요청·원문 인용·근거·Git 참조·기존 저장 기록은 그대로 표시합니다. 언어를 바꿔도 과거 요약을 다시 번역하거나 모델을 호출하지 않습니다. 새 요약은 설정으로 결정한 실제 언어를 요청 시점에 고정하며, 원문 근거는 원래 언어를 유지합니다. 읽기 화면의 고정 안내는 열람 당시의 원본 자료로 다시 표시하며 내용·범주·시각을 유지합니다. 화면 선택 중 언어가 바뀌면 선택을 해제하고 안내합니다.


## 모델 사용량과 저장

기본 요약 모델은 **gpt-6-luna / reasoning effort medium · Standard**입니다. 우클릭 또는 `m` 메뉴의 **요약 모델…**에서 모델을 고른 뒤 그 모델이 지원하는 추론 강도를 골라 `Enter`로 저장합니다. `Esc`는 저장 없이 이전 단계로 돌아가거나 닫습니다. 메뉴에서 모델 목록을 열거나 설정을 저장하는 동작은 요약을 실행하거나 기존 기록을 다시 쓰지 않습니다.

모델 목록은 설치된 Codex의 별도 app-server에서 조회한 텍스트 모델과 지원 강도입니다. 표시된 모델은 계정의 실제 사용 권한이나 성공적인 요약을 보장하지 않으며 번들·캐시 목록일 수 있습니다. 목록을 읽을 수 없거나 현재 설정이 목록에 없어도 설정을 유지하고, 실패를 이유로 기본 모델로 바꾸지 않습니다. Maeklog는 별도의 영구 모델 목록 캐시를 저장하지 않습니다. 설정 화면의 `r`은 목록만 다시 조회합니다.

모델 설정은 같은 Maeklog 설정 디렉터리를 사용하는 모든 탭에 적용됩니다. `HERDR_PLUGIN_CONFIG_DIR`가 있으면 그 디렉터리를 사용합니다. 설치된 `bin/maeklog-hook`에서 실행하고 같은 설정 디렉터리의 `hook-runtime.json`이 유효하면 해당 디렉터리를 사용하므로 패널과 훅이 같은 모델 설정을 읽습니다. 그 외의 기본 파일은 `$XDG_CONFIG_HOME/herdr/plugins/config/maeklog/model-settings.json` 또는 `$HOME/.config/herdr/plugins/config/maeklog/model-settings.json`입니다. 인식한 설치 훅의 실행 설정이 손상되면 모델 설정 위치를 바꾸지 않고 오류를 알립니다. Codex의 일반 모델 설정은 바꾸지 않습니다.

```sh
"$maeklog_root/target/release/maeklog" model show
"$maeklog_root/target/release/maeklog" model list
"$maeklog_root/target/release/maeklog" model set MODEL --effort EFFORT
"$maeklog_root/target/release/maeklog" model set MODEL
```

`model show`는 저장된 모델 설정과 언어 설정으로 결정한 실제 언어를 읽습니다. `model list`는 목록 조회만 하고, `model set`은 조회 결과의 모델·강도를 검증한 뒤 저장합니다. `--effort`를 생략하면 목록이 제공한 기본 강도를 쓰며 지원 강도가 없는 모델에는 강도 override를 붙이지 않습니다. 잘못된 입력·지원하지 않는 강도·목록 조회 실패는 저장을 막고 현재 설정을 유지합니다. 설정 파일이 없으면 원래 기본값을 사용하며, 손상된 파일은 오류로 알립니다.

설정 변경은 이후 시작하는 요약에 적용됩니다. 완료 대화 요약은 모델 실행 시점에 모델·강도·언어 설정으로 결정한 실제 언어를 고정하고, `s`의 현재 진행 요약은 명시적으로 요청한 시점에 고정합니다. 이미 실행 중인 요청은 기존 설정을 유지합니다. 같은 진행 기록의 캐시는 모델·강도·실제 언어까지 같을 때만 재사용합니다. Auto와 직접 선택한 언어가 같은 실제 언어로 해석되면 캐시를 재사용하며, 다른 설정으로 다시 요청한 결과를 늦게 끝난 이전 요청이 덮어쓰지 못합니다. 구버전의 완료 캐시는 읽을 수 있지만 새 설정의 요청에 재사용하지 않고, 구버전의 대기/실행 상태는 명시적 재요청이 필요합니다.

요약은 별도 임시 Codex CLI에서 사용자 설정을 무시하고, hooks를 비활성화한 read-only sandbox와 schema v6를 사용합니다. 서비스는 Standard를 유지하며 별도 제목 생성 모델은 없습니다. 모델의 의미 판단이 틀릴 수 있으므로 중요한 기록은 근거로 확인하세요. 모의 테스트는 실제 모델의 품질을 보증하지 않습니다.

- 완료 대화 수집: 사용자 요청·최종 답변·중단 사실과 세션 연결. 현재 진행 캐시는 별도로 공개 설명·계획·도구 활동 메타데이터만 보존합니다. 비공개 추론과 도구 출력 본문은 수집하지 않습니다.
- 상태 루트당 동시 최대 3작업, 탭당 한 작업, 같은 탭·브랜치 추가 직렬화.
- 배치 최대 8개 이벤트·16,000자 기준. 단일 큰 완료 턴은 통째로 처리하는 기존 예외 유지.
- 요약 timeout 180초. 같은 완료 작업 최대 3회, 실패 후 60초·180초 대기. 새 대화가 와도 이전 실패의 한도는 남음.
- 모델에는 전체 원장 대신 최대 24개 기록·12개 상태·합계 12,000자 이내의 부분 색인만 제공. 조건은 항목 단위로 유지.
- 추가 모델 사용량이 발생하며 금액 기준 예산 상한은 없음.

주요 파일:

모델 설정은 위의 독립 설정 디렉터리에 저장하고, 아래 표는 상태 루트 기준입니다. 실제 상태 루트는 설정 폴더의 `hook-runtime.json`에 있는 `state_dir`로 확인합니다. Herdr 기본 설치에서는 `~/.local/state/herdr/plugins/maeklog`를 사용합니다. 일반 CLI를 별도 환경·실행 설정 없이 실행할 때의 fallback은 `$XDG_STATE_HOME/maeklog` 또는 `~/.local/state/maeklog`입니다.

| spaces/SPACE/selected-current.json | v0.12 정확한 처리 ID + 최신 Space 상태의 저장 기준 |
| spaces/SPACE/current.json / cursor.json | 호환 스냅샷 / 연속 처리 범위. 최신 처리 번호와 항상 같지는 않음 |
| spaces/SPACE/inbox.jsonl | 미처리 원문. 이전 날짜·보류 원문도 여기에 남음 |
| spaces/SPACE/daily-restrictions.json | 재활성화에서 수동 보류한 이벤트 ID |
| spaces/SPACE/manual-day.json | 사용자가 지정한 날짜·고정 이벤트 집합·참여 세대 |
| spaces/SPACE/daily-retries.json | 작업별 재시도 한도 |
| spaces/SPACE/participation.json, ui.json | Space 수집 / 패널 표시 설정 |
| spaces/SPACE/reducer-failure.json | 마지막 응답 검증 실패의 단계·원인·선택된 모델 입력/원문·최종 응답. 민감한 진단 자료이며 최대 2 MiB, 초과 시 본문 생략 표시 |
| spaces/SPACE/timeline.jsonl, legacy-snapshots/SPACE/ | 기존 요약 및 미연결 자료 |

저장 루트 우선순위는 MAEKLOG_STATE_DIR → 설치된 hook-runtime.json → HERDR_PLUGIN_STATE_DIR → XDG 상태 경로입니다. 런타임 설정은 명시한 HERDR_PLUGIN_CONFIG_DIR, 설치된 bin/maeklog-hook의 설정 디렉터리, 또는 일반 CLI의 기본 Maeklog 설정 디렉터리에서 읽습니다. 새 설치는 Maeklog의 독립 경로를 사용합니다. 기존 저장소의 자동 탐색이나 이관은 없습니다. 저장 위치를 바꾸는 명시적 실행 설정은 고급 설정이며, 기록 복사·이관 기능과는 다릅니다. 디렉터리 0700, 파일 0600이며 암호화 저장소가 아닙니다. 요약 대상 대화·부분 색인은 모델 서비스로 전달됩니다.

성공 후 선택한 대기 원문은 제거하지만 짧은 근거 인용·출처는 원장에 남습니다. 날짜 보류는 삭제가 아니며 과거 파일을 별도 백업으로 복제할 필요가 없습니다.

### 삭제

```sh
"$maeklog_root/target/release/maeklog" action clear-records
"$maeklog_root/target/release/maeklog" memory clear EXACT_KEY --confirm-shared EXACT_KEY
```

`action clear-records`는 그 Space의 사적 대기열·요약·날짜 요청/재시도·미연결 자료를 지우고 끈 상태로 둡니다. 브랜치 범위의 누적 기록 기여는 남습니다. `memory clear`는 모든 관련 Space가 꺼져 있고 해당 대기열이 비어 있어야 하며 정확한 키를 두 번 지정해야 합니다.

`memory clear`도 Codex 원본·다른 Space의 별도 스냅샷·백업까지 지우는 명령은 아닙니다. 최소 범위 식별·처리 지문·잠금·꺼짐 정보는 남습니다. 자체 복구 기능은 없습니다.


## 브랜치·Space와 과거 기록

기록의 단위는 정규화한 Git common directory + 브랜치명 + 보수적인 reflog 세대 식별값입니다. 같은 저장소·브랜치도 탭이 다르면 분리합니다. 이전 공용 브랜치 기록은 별도 보관합니다. 같은 원격의 별도 clone은 자동 병합하지 않습니다.

수집 시점의 저장소·브랜치·HEAD·worktree·Space·세션을 출처로 남깁니다. A의 대기 대화를 B 체크아웃 후 처리해도 A에 저장합니다. 다른 브랜치를 잠깐 언급했다고 귀속을 옮기지 않습니다.

브랜치 생성 전, detached HEAD, reflog 없음, 구버전 귀속 미확인 자료는 미연결로 보존합니다. 이름 변경·삭제 후 재생성·reflog 교체도 임의 연결하지 않습니다. 구버전 요약 변경 이력을 개별 확정 결정·완료로 추정 변환하지 않습니다.

```sh
"$maeklog_root/target/release/maeklog" memory list
"$maeklog_root/target/release/maeklog" memory show EXACT_KEY
"$maeklog_root/target/release/maeklog" memory history EXACT_KEY 1
"$maeklog_root/target/release/maeklog" memory legacy EXACT_SPACE_KEY

# 날짜별 대기 수 확인 / 명시적 실행
"$maeklog_root/target/release/maeklog" daily list
"$maeklog_root/target/release/maeklog" daily request YYYY-MM-DD
"$maeklog_root/target/release/maeklog" daily request unknown
```

`memory list`가 출력한 정확한 기록 키를 `EXACT_KEY` 자리에 사용하세요. `daily` 명령은 현재 Space의 수집된 대기열을 대상으로 합니다. unknown은 시각 미확인/여러 날짜에 걸친 완료 대화입니다. 같은 브랜치라도 다른 탭의 수집 설정을 바꾸지 않습니다.


## 이슈·PR

현재 대화에서 명시한 작업 참조를 패널 위쪽에 표시합니다. 사용자 요청의 정확한 GitHub URL이나 `owner/repository#142`에서 현재 작업을 인지하고, 참고·비교·인용·과거 언급은 후보로 남깁니다. 주 코딩 에이전트는 현재 턴에 묶인 구조화 보고로 작업 대상·작업 위치·관련 PR을 전달할 수 있습니다. 보고가 없거나 실패해도 기존 연결을 지우지 않습니다. [Codex 인계 계약](../integrations/codex/task-reports.md).

‘#142 말고 #156 작업해줘’처럼 명시적으로 바꾸면 새 대상을 즉시 지정하고 확인 중 상태로 표시합니다. GitHub 조회 실패는 새 대상의 확인 상태에 남고 기존 대상은 이전 연결로 보존합니다. 대화별 연결은 새 대화에 승계하지 않으며 같은 대화를 재개하면 복원합니다. 수동 정정 뒤 늦게 도착한 옛 요청의 보고는 그 정정을 덮지 않습니다.

작업 참조와 **저장된 브랜치 기록**은 따로 표시합니다. `main`에서 다른 worktree를 작업해도 기존 원장의 귀속을 바꾸지 않습니다. 관련 PR은 검증된 작업 위치와 PR의 저장소·브랜치·closing issue가 일치할 때 연결하며, PR 생성 보고나 병합 사실을 작업 완료로 취급하지 않습니다.

`l`로 **작업 연결 정정**을 열고 `↑↓`로 후보를 고릅니다. `Enter`는 적용 후 닫기, `Esc`는 취소, `a`는 번호/URL 입력, `n`은 ‘연결 안 함’ 행 선택, `u`는 이전 연결로 되돌리기, `o`는 선택한 링크 열기입니다. `n`도 `Enter`를 눌러야 적용됩니다. 입력 중 `Esc`는 입력만 취소하고 후보 화면으로 돌아갑니다. 이 화면과 기본 화면의 `v`는 다시 확인합니다. 기본 화면의 `r`은 완료 대화 반영이며 대문자 `R`에는 동작을 배정하지 않습니다.

기본 화면의 `o`는 대상이 하나면 바로 링크 열기를 요청하고 정정 화면에 결과를 표시합니다. 여러 대상이면 정정 화면에서 골라 `o`를 누릅니다. 링크를 연 뒤 `Esc`로 기본 화면에 돌아옵니다.

확인된 현재 GitHub 저장소에서는 `142`나 `#142`만 입력해도 조회로 이슈·PR 종류를 알아냅니다. 원격이 없으면 `owner/repository#142` 또는 정확한 GitHub URL을 사용하세요. 현재 탭의 주 Codex client가 검증되지 않거나 여러 client로 모호하면 후보 열기만 제공하며 현재 대화 연결을 만들지 않습니다. 이미 실행 중인 검증된 단일 client는 패널 배경 작업에서 연결합니다.

GitHub 조회는 읽기 전용입니다. 확인 중·확인 실패·사용자 지정 연결 안 함과 브랜치 탐색의 열린 PR 없음·후보 선택 필요·자동 연결 불가를 구분합니다. 인증/네트워크 실패는 마지막 성공 정보와 확인 시각을 보존합니다. 성공 캐시는 60초간 재사용하고 실패는 30초부터 최대 300초까지 재시도 간격을 늘립니다. `h`/`b`/`e` 이동과 텍스트 렌더링은 조회나 보고 수집을 요청하지 않으며, 기본 화면의 `r`은 기존 대화 요약 재시도 기능입니다.

현재 대화의 참조가 없으면 기존 원격 저장소·브랜치 탐색을 보조로 사용합니다. 같은 저장소와 브랜치의 열린 PR이 하나면 연결하고, 선택된 PR의 closing issue가 하나면 이슈를 연결합니다. 아직 push하지 않은 로컬 커밋에도 같은 브랜치 연결을 유지하며, 여러 열린 PR과 닫힘·병합 PR은 선택 후보로 남깁니다. 아래 기존 **브랜치 연결 CLI**는 그대로 사용할 수 있습니다. `links auto`는 이 CLI의 수동 선택을 자동 탐색으로 되돌립니다.

```sh
"$maeklog_root/target/release/maeklog" links primary issue owner/repository#142
"$maeklog_root/target/release/maeklog" links primary pr owner/repository#167
"$maeklog_root/target/release/maeklog" links add issue owner/repository#143
"$maeklog_root/target/release/maeklog" links remove issue owner/repository#143
"$maeklog_root/target/release/maeklog" links none issue
"$maeklog_root/target/release/maeklog" links none pr
"$maeklog_root/target/release/maeklog" links auto issue
"$maeklog_root/target/release/maeklog" links auto pr
"$maeklog_root/target/release/maeklog" links show
"$maeklog_root/target/release/maeklog" links refresh
```
